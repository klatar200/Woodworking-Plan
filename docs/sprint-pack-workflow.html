The sprint pack: a file-backed loop for Claude + Cursor

Both agents already read your repo. So stop routing their conversation through your clipboard. One folder per sprint becomes the only interface between them — and you go from pasting mega-prompts to typing four short lines.

Claude Code — plans & verifies You — 4 messages, 1 command Cursor — implements & grades

The one idea

The folder is the message bus

Today the sprint's state lives in two chat windows and your clipboard. Every fix round, Claude regenerates a full prompt, you paste it, Cursor re-ingests it, Cursor writes long prose, you paste that back. You pay for the same context four or five times per round.

Move that state into sprints/47/. Claude writes the plan and the bar. Cursor writes the code and the grade. Each reads what the other left. You carry a pointer, not the payload.

A side effect that matters as much as the token savings: if a Claude session hits its limit or resets context mid-sprint, you lose nothing. The sprint is on disk, not in a transcript.

Artifact

What lives in the sprint pack

Seven files, one owner each. No file is written by two actors — that's what keeps the grade honest and the diffs clean.

sprints/47/
File Written by Contents
GOAL.md Claude Objective, explicit out-of-scope, user impact. Under 40 lines.
PLAN.md Claude Ordered tasks with real file paths, guardrails, and the CLAUDE.md §7 invariants each task must not break.
ACCEPTANCE.md Claude BUILD_PLAN §6 categories instantiated for this sprint as binary checks. Written before any code exists.
verify.txt Cursor Raw, unedited output of npm run verify. Machine evidence, not prose.
SCORECARD.md Cursor Pass/fail against every ACCEPTANCE.md line, citing verify.txt. The percentage falls out of the count.
changes.diff You One command. What Claude reads instead of re-auditing the repo.
FIXES.md Claude Gaps only, with exact remediation. Appended per round — never a rewritten plan.

Context files stay exactly where they are: CLAUDE.md, AGENTS.md, BUILD_PLAN.md, BUSINESS_PLAN.md, DESIGN_BRIEF.md, DECISIONS_LOG.md. No new architecture doc. A second source of truth drifts, and drift is the failure mode your §7 invariants exist to prevent.

Contracts

Exactly what each actor may and may not do

Claude Code

  • Writes GOAL, PLAN, ACCEPTANCE, FIXES.
  • Derives ACCEPTANCE from BUILD_PLAN §6 — same bar, instantiated per sprint.
  • Audits from changes.diff and verify.txt.
  • Browser-verifies only the manual paths ACCEPTANCE names.
  • Owns §7 invariant review, security, multi-tenancy, architecture.
  • Closes the sprint into SPRINT_LOG / BUILD_PLAN.

Never: re-audits the repo at session start. Never writes SCORECARD — the actor that sets the bar doesn't get to declare it met.

Cursor

  • Implements PLAN.md in order.
  • Runs npm run verify, pipes raw output to verify.txt.
  • Grades every ACCEPTANCE line pass/fail in SCORECARD, citing evidence.
  • On a fix round, reads FIXES.md and nothing else.
  • Auto model for rote work; premium only for the hard slice.

Never: edits ACCEPTANCE.md. Never marks a check passed without a verify.txt line or a named file:line. Never expands scope beyond PLAN.md.

You

  • Supply the change list once, at sprint open.
  • Type four short pointers (below).
  • Run git — push packs out, pull work back, cut the diff. Both agents are read-only w.r.t. git, and Cursor Cloud sees nothing you haven't pushed.
  • Make the calls CLAUDE.md §4 reserves for you: money, vendors, legal, branding, scope.

Never again: paste a plan, a scorecard, or a fix list between windows.

Your part, verbatim

The four messages and one command

This is the whole of your manual involvement per sprint. Only the sprint number and the opening change list ever change.

  1. Open the sprint — to Claude Code 
    Plan sprint 47. Changes I want:
- <your list, in your own words>

Write sprints/47/GOAL.md, PLAN.md, ACCEPTANCE.md.
Agent-focused, not human-readable. Don't re-audit the repo.
    Model: Opus. The only step that needs the expensive model's judgment.
  2. Hand off — to Cursor 
    Read sprints/47/. Implement PLAN.md in order.
Then run: npm run verify > sprints/47/verify.txt 2>&1
Grade every ACCEPTANCE.md check in sprints/47/SCORECARD.md,
citing verify.txt or file:line as evidence. Don't edit ACCEPTANCE.md.
    Four lines instead of a two-thousand-word prompt. Cursor opens the pack itself.
  3. Publish the pack, then fetch Cursor's branch — PowerShell, your box 
    # after step 1, so Cursor Cloud can see the pack
node scripts/verify.mjs lock sprints/75
git add -A; git commit -m "sprint 75: pack"; git push

# after step 2 — substitute the real branch name
git fetch origin
git diff "origin/main...origin/cursor/<branch>" --output=sprints/75/changes.diff
    The last line is the whole trick — Claude reads a few hundred diff lines instead of re-reading a repo of thousands of files. Three details are load-bearing: --output= rather than > (PowerShell redirection writes UTF-16LE), the quotes (PowerShell eats a bare @{), and three dots (what the branch added since it diverged). Merge only after the audit passes.
  4. Audit — to Claude Code 
    Audit sprints/47. Append FIXES.md — gaps only, exact remediation.
    Model: Sonnet. Reading a diff against a written bar is mechanical. Switch back to Opus only if it flags an architecture or security problem.
  5. Fix round — to Cursor, then repeat step 03 
    Read sprints/47/FIXES.md. Apply only those fixes.
Re-run verify, update verify.txt and SCORECARD.md.
    Cursor Auto handles most fix rounds. Stop at three and escalate rather than grinding.
  6. Close — to Claude Code once the grade clears 95% 
    Sprint 47 passed. Log it and write sprints/48.
    Model: Opus. Then you're back at step 02 with no re-audit and nothing re-explained.

Economics

Where the savings actually come from

Directional, not measured. The ordering below is structural and reliable; the magnitudes are estimates worth confirming against your own usage after two sprints.

Per phase, per sprint
Phase Today Under the pack Effect
Session open Claude re-audits the architecture Reads CLAUDE.md + BUILD_PLAN §4 + the pack largest single cut
Verification Opus reads Cursor's prose, re-reads source Sonnet reads verify.txt + changes.diff large — cheaper model, smaller input
Fix rounds 2–3 Full prompt regenerated and re-pasted each round FIXES.md delta only, on both sides large — scales with round count
Plan handoff Prompt billed twice: Claude writes it, Cursor ingests it Written once to disk; you paste a pointer moderate
Cursor model mix Premium model carries the fix rounds Auto handles bounded FIXES.md deltas moderate — hits your Cursor cap
Context loss Limit hit mid-sprint means redoing the setup State on disk; resume cold removes a whole failure mode

Time

Roughly six large copy-pastes per sprint become four one-line messages and one shell command. You also stop reading long agent prose to decide what to forward — SCORECARD is a pass/fail list, FIXES is a delta.

Effort

You stop being the integration layer. What's left is the part only you can do: supplying the change list and making the §4 business calls.

Quality

The bar is written before the code, by a different actor than the one graded against it. That closes the self-grading hole — today Cursor both does the work and decides it's done.

Mind map

How it ties together

Everything radiates from one folder. Nothing crosses between agents except through it.

Claude writes

  • GOAL.md — objective + out-of-scope
  • PLAN.md — tasks, paths, §7 guardrails
  • ACCEPTANCE.md — §6 bar, binary, up front
  • FIXES.md — gaps only, per round
The interface sprints/47/ The only thing both agents read — carried between them on origin/main, since Cursor Cloud has its own clone. Survives a context reset. Reviewable in git.

Cursor writes

  • source code — PLAN.md in order
  • verify.txt — raw machine evidence
  • SCORECARD.md — graded against Claude's bar

You supply

  • the change list — once, at open
  • 4 pointer messages — never a payload
  • changes.diff — one git command
  • §4 business calls — money, scope, brand

What it buys

  • No re-audit — the context files already hold it
  • Sonnet-able verify — diff against a written bar
  • Delta fix loops — rounds 2–3 get cheap
  • Honest grade — bar author ≠ grader
  • Resumable — sprint state lives on disk

What has to be built first — and by whom

Piece What it is Built by

sprints/_template/ Empty GOAL / PLAN / ACCEPTANCE skeletons so every pack has the same shape. Claude

first git commit Landing the scaffold on main. You

Nothing here needs Cursor. It's four small files, one line in package.json, and edits to the two agent-contract docs — and those docs are Claude's own operating instructions, so Claude should own them. Delegating the setup would spend a premium Cursor request to save nothing.

The one thing Cursor genuinely needs is the standing prompt from step 02 — and that's a permanent four-liner you reuse every sprint, not a setup task.
